# Self-hosted Windows runner for DocInspector

## Purpose

Use a trusted Windows machine to execute the expensive Playwright browser gate without consuming hosted-runner minutes.

## Safety boundary

A self-hosted runner executes repository workflow code on the machine. Register only a dedicated/trusted machine and do not expose sensitive personal files or credentials to the runner account.

## One-time registration

In GitHub, open the DocInspector repository and go to:

`Settings → Actions → Runners → New self-hosted runner`

Choose Windows x64 and follow the commands generated by GitHub on the target machine.

During configuration, add the custom label:

`docinspector-e2e`

The workflow expects these labels:

`self-hosted`, `Windows`, `X64`, `docinspector-e2e`.

Run the agent interactively for the first validation. After the workflow is stable, it can optionally be installed as a Windows service so it is available whenever the machine is on.

## Validation

From GitHub Actions, run `Local Windows E2E Runner` manually.

A successful run must complete:

1. checkout;
2. Node.js 22 setup;
3. npm dependency installation;
4. Chromium/WebKit installation;
5. deterministic quality gate;
6. Playwright E2E;
7. artifact upload.

Only after this smoke run is stable should the normal PR E2E job be migrated to the local runner.

## Availability rule

Do not make the self-hosted runner a required PR gate unless the machine is expected to be online during development. An offline required runner leaves pull requests queued rather than failed.
